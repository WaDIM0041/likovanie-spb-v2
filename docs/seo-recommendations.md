# SEO-рекомендации для сайта школы танцев «Ликование»

Дата исследования: 15 октября 2026 года.

Проверены опубликованная версия [v2 на GitHub Pages](https://wadim0041.github.io/likovanie-spb-v2/), её HTML и действующий сайт [likovanie-spb.ru](https://likovanie-spb.ru/).

GitHub Pages используется для временного просмотра. Позже новая версия будет перенесена на основной хостинг. Рекомендации ниже относятся прежде всего к подготовке и развитию сайта на постоянном домене.

## 1. Главная рекомендация

Сохранить домен `likovanie-spb.ru` и заменить на нём действующий сайт обновлённой версией. Сам по себе другой хостинг не повышает позиции. Значение имеют доступность сайта, полезное содержание, скорость, локальная информация и корректный перенос существующих адресов.

Временную v2 оставить с `noindex`. Перед запуском на основном домене открыть индексацию только нужных публичных страниц и проверить, что технические копии не попали в поиск.

## 2. Результаты проверки

### Что уже хорошо

- Главная v2 доступна с HTTP-статусом `200`.
- Указаны русский язык страницы и настройки мобильного отображения.
- Title конкретный: «Школа танцев в Красногвардейском районе СПб — Ликование».
- Description описывает возраст, город, услуги и бесплатное пробное занятие.
- На странице один H1; есть структура разделов с H2 и H3.
- Основная информация доступна в исходном HTML: педагоги, цены, расписание, адрес и телефон.
- Есть JSON-LD с данными организации, сайта и страницы; JSON синтаксически корректен. Проверка полного соответствия требованиям поисковых систем нужна перед запуском.
- Есть WebP-версии фотографий; большинство изображений загружается отложенно. Для главной сценической фотографии задан высокий приоритет загрузки.
- Контактный раздел ссылается на реальную карточку школы в Яндекс Картах.

### Что требует внимания

| Наблюдение | Значение и действие |
| --- | --- |
| В v2 установлен `noindex,nofollow` | Подходит для временного просмотра. Убрать с предназначенных для поиска страниц при запуске на основном домене. |
| В v2 нет `canonical` и `sitemap.xml` | Подготовить постоянные адреса страниц, canonical и карту сайта к запуску. |
| В v2 нет `og:image` и `og:url` | Добавить изображение и адрес для аккуратного отображения ссылок в мессенджерах и соцсетях. Это преимущественно улучшение представления, а не самостоятельный фактор роста позиций. |
| Основной домен уже работает на Tilda и имеет canonical и sitemap | При замене сохранить полезные настройки, существующие страницы и адреса. Не считать перенос запуском домена с нуля. |
| Детские и взрослые программы объединены на одной главной | Подготовить самостоятельные страницы для разных потребностей посетителей. |
| Переключение возрастов подменяет один текст через JavaScript | Важные описания всех программ должны быть доступны без нажатия кнопок: в HTML или на связанных страницах. |
| Большинство фото галереи имеют alt вида «фотография N» | Добавить содержательные описания по фактическим материалам. |
| Большинство изображений без HTML-атрибутов `width`/`height` | Проверить резервирование места стилями и стабильность макета; добавить размеры или `aspect-ratio`, где их не хватает. Само отсутствие атрибутов ещё не доказывает скачки страницы. |
| Нет набора ширин изображений через responsive `srcset`/`sizes` | Подготовить подходящие размеры для мобильных экранов и больших дисплеев. |
| Публично открывается техническая копия `/design/index.html` | На основном хостинге исключить её из публикации либо настроить корректную обработку этого адреса. Сейчас у неё есть `noindex`. |

### Важное уточнение про robots.txt на GitHub Pages

Поисковые роботы читают файл в корне хоста: `https://wadim0041.github.io/robots.txt`. Файл `/likovanie-spb-v2/robots.txt` не управляет индексацией проекта, поскольку расположен в подпапке.

Во время проверки корневой robots.txt разрешал обход и содержал ссылки на другой домен — `annakam.ru`. Для временной v2 опираться на её метатег `noindex`; на основном хостинге создать собственный robots.txt в корне `likovanie-spb.ru`.

Не блокировать обход страниц, если необходимо, чтобы робот увидел их `noindex`. `robots.txt` не является защитой конфиденциальных данных.

## 3. Приоритеты работ

### Приоритет 1 — согласовать предложения школы

Свести в единую таблицу: возраст → программа → длительность и частота занятий → педагог → расписание → стоимость → условия пробного занятия.

Обнаружены неоднозначности, которые нельзя исправлять предположением:

- В подборе есть возраст «2,5–3 года», в расписании — «2,5–3,5 года», а тариф 5 000 ₽ подписан для «3–4 лет».
- В расписании группа малышей занимается дважды по 30 минут; у тарифа указано два часа в неделю. Нужно установить, к какой группе относится тариф.
- В пятницу для Anti-age complex указано `11:00–21:00`. Требуется подтверждение школы.
- Названия «Бережный фитнес» и «Anti-age complex» нужно согласовать между направлениями, формами и расписанием.

Ясные условия помогают посетителю выбрать группу и повышают доверие к коммерческой информации.

### Приоритет 2 — создать полезные страницы программ

Начать с ограниченного набора страниц с самостоятельным содержанием:

| Предлагаемый URL | Тема и потребность посетителя |
| --- | --- |
| `/` | Школа танцев в Красногвардейском районе Санкт-Петербурга; обзор и выбор программы. |
| `/children/` | Детские программы, возрастные группы и путь от первого занятия к выступлениям. |
| `/children/toddlers/` | Занятия от 2,5 лет, если для них достаточно отдельных сведений. |
| `/adults/` | Реально действующие занятия для взрослых. |
| `/adults/body-ballet/` | Боди-балет, если это самостоятельная услуга с собственным расписанием и условиями. |
| `/contacts/` | Адрес, вход, маршрут, режим связи и контакты. |
| `/schedule/` | Актуальные группы, дни, время и педагоги. |
| `/prices/` | Тарифы, состав абонементов, оплата и условия посещения. |

Это предлагаемая структура, а не уже опубликованные страницы. Точные URL выбрать после сверки существующих адресов и поисковых данных.

На странице программы разместить:

- для кого она предназначена и можно ли без подготовки;
- чему посвящены занятия и как они проходят;
- возраст, длительность и частоту занятий;
- педагога со ссылкой на его сведения;
- действующее расписание и стоимость;
- реальные фотографии занятий;
- условия пробного занятия и простой способ записи;
- ответы на вопросы именно этой аудитории.

Не создавать десятки одинаковых страниц под районы и станции метро. Не представлять элементы комплексной программы как отдельные продаваемые курсы, если школа их отдельно не предлагает.

### Приоритет 3 — уточнить первый экран и заголовки

Сохранить слоган «От первого движения — к большой сцене» и добавить заметное пояснение:

> Школа танцев для детей и взрослых в Красногвардейском районе Санкт-Петербурга.

Текущий слоган в H1 не является технической ошибкой. Цель изменения — сразу объяснить услугу и местоположение. Не нужно многократно повторять одинаковые ключевые слова.

Каждой новой странице дать собственные title, H1 и description. Description должен честно описывать страницу; поисковик может сформировать иной сниппет.

### Приоритет 4 — локальный поиск

- Проверить права на карточку школы в Яндекс Бизнесе и наличие актуальной карточки в 2ГИС.
- Согласовать название, адрес, телефон, основной HTTPS-адрес сайта, категории услуг и часы работы.
- Проверить регион «Санкт-Петербург» в Яндекс Вебмастере.
- Добавить фото входа, этаж/зал и понятный маршрут.
- Указывать метро и время в пути только после проверки.
- Поддерживать актуальные фотографии, услуги и расписание в карточках.
- Просить родителей оставлять настоящие отзывы и отвечать на них.

Ссылка на Яндекс Карты на сайте уже есть. Наличие встроенной карты само по себе не является требованием SEO. Права владельца и полнота карточек в рамках проверки не подтверждались.

### Приоритет 5 — содержание и доказательства

Добавить проверенные ответы на вопросы:

1. Можно ли начать без опыта и специальной подготовки?
2. Как проходит и сколько длится первое занятие?
3. Какую одежду и обувь взять?
4. Могут ли родители присутствовать?
5. Как выбрать возрастную группу?
6. Как действуют абонемент, пропуски и переносы?
7. Обязательно ли участвовать в выступлениях и конкурсах?

Отзывы дополнить датами и ссылками на источники, когда они доступны. Для достижений указать конкретные конкурсы, год, результат и подтверждающие материалы.

Формулировка «более 36 лет» в текущей карточке относится к опыту педагога. Не превращать её без проверки в возраст школы.

Для фотографий и видео добавить реальные названия постановок/событий, даты и подписи. Не выдумывать их по внешнему виду кадров.

Вопросы и ответы полезны посетителям и содержанию страницы. Не обещать специальный FAQ-сниппет: по актуальному сообщению Google эта функция прекращена с 7 мая 2026 года.

## 4. Скорость и motion-эффекты

Сохранить сценическую концепцию, проверяя её влияние на мобильную загрузку и отзывчивость:

- Главное содержание и кнопка записи должны появляться без ожидания завершения анимации.
- Проверить, что тяжёлый рендер и видео приостанавливаются вне экрана и в скрытой вкладке.
- Подготовить несколько размеров фотографий для разных экранов.
- Отложить загрузку обложек и данных видео до приближения к соответствующему блоку.
- Проверить резервирование места для фото, видео, шрифтов и 3D-композиции.
- Проверить загрузку на обычном мобильном устройстве и ограниченном соединении.

Целевые значения Core Web Vitals:

| Метрика | Хороший результат |
| --- | --- |
| LCP — появление основного содержимого | Не более 2,5 секунды. |
| INP — отзывчивость на взаимодействия | Не более 200 миллисекунд. |
| CLS — стабильность макета | Не более 0,1. |

Это целевые значения, а не измеренные результаты сайта. Для оценки нужны мобильные лабораторные проверки и полевые данные, если для сайта накоплено достаточно посещений. Размер HTML сам по себе не показывает скорость всей страницы.

## 5. Техническая проверка перед переносом

- [ ] Сохранить домен `likovanie-spb.ru` и доступы к его управлению.
- [ ] Выгрузить существующие URL, поисковые запросы и посадочные из Вебмастера и Search Console, если доступы есть.
- [ ] Проверить, какие страницы получают посещения и внешние ссылки.
- [ ] Сохранить полезные существующие URL; для изменённых подготовить соответствующие 301/308-редиректы.
- [ ] Не перенаправлять все удалённые страницы на главную без смыслового соответствия.
- [ ] Проверить HTTPS и единый вариант домена с перенаправлением альтернативных вариантов.
- [ ] Установить canonical на постоянные адреса публичных страниц.
- [ ] Удалить случайный `noindex` с предназначенных для поиска страниц.
- [ ] Оставить временные и технические копии вне индекса и sitemap.
- [ ] Создать robots.txt в корне основного домена; не закрывать нужные страницы и ресурсы.
- [ ] Создать sitemap.xml из реальных канонических URL со статусом `200`.
- [ ] Указывать `lastmod` по фактическому существенному обновлению страницы.
- [ ] Проверить настоящие HTTP-ответы `404` для несуществующих адресов.
- [ ] Проверить внутренние ссылки и значимые старые якоря.
- [ ] Добавить `og:url` и `og:image` для обмена ссылками.
- [ ] Проверить JSON-LD и его соответствие видимому содержанию.
- [ ] По возможности заменить внешний адрес логотипа Tilda в разметке адресом на собственном домене.
- [ ] Добавлять сведения о часах работы, ценах и услугах только по подтверждённым данным.
- [ ] Проверить мобильные страницы, загрузку изображений, меню, галерею и запись.
- [ ] Отправить sitemap и ключевые страницы на проверку/переобход в Вебмастере и Search Console.

При переносе на другой хостинг с сохранением домена и URL менять адрес сайта в поисковых панелях обычно не требуется. Важно обеспечить непрерывную доступность и сохранить подтверждение прав. Инструменты переезда применять при фактической смене адреса по инструкциям соответствующей поисковой системы.

## 6. Аналитика и оценка результата

Для измерения подключить или проверить Яндекс Вебмастер, Google Search Console и систему аналитики с учётом согласованной обработки данных.

Отслеживать:

- индексирование нужных страниц и ошибки обхода;
- показы, клики и запросы по бренду, району, возрастам и программам;
- переходы из карточек организации;
- органические переходы на конкретные программы;
- клики по телефону и мессенджерам;
- фактически полученные обращения и записи на пробное занятие.

Текущие формы подготавливают письмо в почтовом приложении. Клик по кнопке не подтверждает отправку письма и получение заявки школой. Эти действия учитывать раздельно.

Проверять техническое состояние сразу после запуска и в последующие недели. Содержательные результаты оценивать по накопленным данным с учётом сезонности набора; не обещать определённые позиции или число заявок без измерений.

## 8. Порядок внедрения

1. Согласовать возрастные группы, тарифы, расписание и названия программ.
2. Подготовить полезные страницы основных программ и контактов.
3. Усилить локальную информацию, отзывы и подтверждённые достижения.
4. Подготовить технический комплект и карту переноса URL.
5. Перенести сайт на основной хостинг с сохранением домена.
6. Проверить индексацию, скорость и получение обращений.
7. Развивать страницы по фактическим запросам и обращениям.
